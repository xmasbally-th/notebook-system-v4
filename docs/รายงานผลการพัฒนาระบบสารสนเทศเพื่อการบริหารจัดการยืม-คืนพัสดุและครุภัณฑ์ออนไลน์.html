    • บทสรุปสำหรับผู้บริหาร (Executive Summary)

    คณะวิทยาการจัดการ มหาวิทยาลัยราชภัฏลำปาง มีภารกิจในการสนับสนุนการจัดการเรียนการสอน การวิจัย และการบริการวิชาการ ซึ่งจำเป็นต้องมีอุปกรณ์คอมพิวเตอร์พกพา (Notebook) และครุภัณฑ์เทคโนโลยีสารสนเทศสำหรับให้อาจารย์ บุคลากร และนักศึกษายืมใช้งาน ในอดีตกระบวนการยืม-คืนดำเนินงานผ่านการจดบันทึกลงสมุดและการประยุกต์ใช้ Google Forms ซึ่งพบข้อจำกัดวิกฤตหลายประการ ได้แก่ ไม่สามารถตรวจสอบสถานะความพร้อมของอุปกรณ์แบบเรียลไทม์ เกิดปัญหาการยืมอุปกรณ์ซ้ำซ้อน การติดตามอุปกรณ์ที่เกินกำหนดส่งคืนทำได้ล่าช้า และขาดระบบฐานข้อมูลเชิงสัมพันธ์ที่มีความมั่นคงปลอดภัยตามมาตรฐานพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล (PDPA)

    เพื่อแก้ไขปัญหาดังกล่าวอย่างยั่งยืน จึงได้ริเริ่มโครงการ "พัฒนาระบบสารสนเทศเพื่อการบริหารจัดการยืม-คืนพัสดุและครุภัณฑ์ออนไลน์" (Notebook System) ขึ้น โดยออกแบบและพัฒนาระบบเว็บแอปพลิเคชันยุคใหม่ (Cloud-Native Web Application) บนสถาปัตยกรรม Next.js 16 (App Router), React 19, Supabase PostgreSQL พร้อมระบบรักษาความปลอดภัยระดับแถวข้อมูล (Row Level Security - RLS Hardening)

    การดำเนินงานแบ่งออกเป็น 4 มิติหลักที่บูรณาการสอดคล้องกันอย่างสมบูรณ์:

    1. การพัฒนาระบบงาน: พัฒนาระบบบริหารจัดการยืม-คืนพัสดุและครุภัณฑ์ออนไลน์ที่รองรับการใช้งานทุกแพลตฟอร์ม พร้อมนวัตกรรม In-app QR Code Scanner, ระบบยืมด่วน (Instant Borrowing), สถานีบริการด่วนหน้าเคาน์เตอร์ (Staff Fast Counter), ระบบตรวจจับการจองซ้อนทับระดับ Time Slot และระบบพิมพ์สติกเกอร์ QR Code ติดครุภัณฑ์ขนาดมาตรฐาน A4

    2. การจัดทำคู่มือการปฏิบัติงาน: จัดทำชุดคู่มือมาตรฐานครบทุกกลุ่มผู้ใช้ ได้แก่ คู่มือผู้ดูแลระบบ (Admin Manual), คู่มือเจ้าหน้าที่ปฏิบัติการ (Staff Manual) และคู่มือผู้ใช้งานทั่วไป (User Manual) เพื่อให้การปฏิบัติงานเป็นไปอย่างราบรื่นและมีมาตรฐานเดียวกัน

    3. การจัดทำผลงานเชิงวิเคราะห์/ออกแบบ: ออกแบบสถาปัตยกรรมฐานข้อมูลเชิงสัมพันธ์ (ER Diagram & Data Dictionary) ครอบคลุม 4 กลุ่มตารางหลัก และออกแบบแผนผังกระบวนการทำงาน (Workflow Flowcharts) รวม 5 แผนผังหลัก

    4. การจัดทำผลงานเชิงวิเคราะห์/สังเคราะห์: พัฒนาระบบสรุปและรายงานผลสถิติสำหรับผู้บริหาร (Executive Command & Analytics Center) กราฟวิเคราะห์แนวโน้มการใช้งาน และระบบสังเคราะห์แบบประเมินความพึงพอใจ 5 มิติ (Evaluation Analytics Revamp) พร้อมการส่งออกข้อมูล CSV สำหรับการวางแผนเชิงกลยุทธ์

    จากการนำระบบไปใช้งานจริง พบว่าสามารถลดขั้นตอนและเวลาในการปฏิบัติงานของเจ้าหน้าที่ลงได้กว่า 80% ขจัดปัญหาการยืมซ้อนทับได้อย่างสิ้นเชิง (0%) ลดอัตราการส่งคืนล่าช้า และสร้างความโปร่งใสผ่านระบบบันทึกประวัติการปฏิบัติงาน (Audit Trail) ได้ครบถ้วน 100%

    • ส่วนที่ 1: การพัฒนาระบบงาน (System Development)

    "พัฒนาระบบสารสนเทศเพื่อการบริหารจัดการยืม-คืนพัสดุและครุภัณฑ์ออนไลน์ คณะวิทยาการจัดการ"

    1.1 ความเป็นมา สภาพปัญหา และความจำเป็นในการพัฒนาระบบ

    คณะวิทยาการจัดการ มหาวิทยาลัยราชภัฏลำปาง มีการให้บริการครุภัณฑ์คอมพิวเตอร์โน้ตบุ๊คและอุปกรณ์สนับสนุนการศึกษาจำนวนมาก เพื่อรองรับกิจกรรมการเรียนการสอน การสอบประมวลความรู้ การสัมมนา และการปฏิบัติงานนอกสถานที่ของคณาจารย์ บุคลากร และนักศึกษา

    ในอดีต กระบวนการจัดการยืม-คืนใช้รูปแบบการจดบันทึกลงสมุดบัญชี ต่อมาได้ปรับเปลี่ยนมาใช้ Google Forms เพื่อรวบรวมข้อมูลผ่านระบบออนไลน์เบื้องต้น อย่างไรก็ดี จากการวิเคราะห์สภาพแวดล้อมการทำงานจริง พบว่าการใช้ Google Forms และ Google Sheets มีข้อจำกัดที่ส่งผลกระทบต่อประสิทธิภาพการปฏิบัติงาน ดังนี้:

    1. ขาดการแสดงสถานะแบบเรียลไทม์ (Lack of Real-time Status): ผู้ใช้งานไม่สามารถตรวจสอบได้ว่าในขณะนั้นมีเครื่องว่างหรือไม่ รุ่นใดพร้อมใช้งาน ทำให้ต้องเดินทางมาสอบถามเจ้าหน้าที่โดยตรง

    2. ปัญหาการส่งคำขอยืมซ้ำซ้อน (Request Collision): ในช่วงเวลาที่มีความต้องการสูง เช่น สัปดาห์สอบ ผู้ใช้งานหลายรายอาจส่งฟอร์มขอยืมอุปกรณ์เครื่องเดียวกันพร้อมกัน ส่งผลให้เจ้าหน้าที่ต้องคอยติดต่อกลับเพื่อปฏิเสธหรือหาเครื่องทดแทน

    3. การติดตามอุปกรณ์ค้างส่งทำได้ล่าช้า (Inefficient Overdue Tracking): ขาดระบบแจ้งเตือนอัตโนมัติ เจ้าหน้าที่ต้องเปิดสเปรดชีตตรวจสอบรายวันและโทรศัพท์ติดตามผู้ยืมด้วยตนเอง

    4. ความเสี่ยงด้านความปลอดภัยและความถูกต้องของข้อมูล (Data Security & Integrity): ลิงก์สเปรดชีตอาจถูกแชร์หรือแก้ไขโดยไม่ตั้งใจ ขาดการแบ่งสิทธิ์การเข้าถึงอย่างเคร่งครัด และไม่สอดคล้องกับ พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA)

    จากสภาพปัญหาดังกล่าว ผู้จัดทำจึงได้ดำเนินโครงการพัฒนาระบบสารสนเทศเพื่อการบริหารจัดการยืม-คืนพัสดุและครุภัณฑ์ออนไลน์ โดยยกระดับจากระบบบันทึกแบบเดิม สู่ ระบบบริหารจัดการทรัพยากรแบบครบวงจร (Full-cycle Digital Resource Management Platform)

    1.2 วัตถุประสงค์และเป้าหมายของโครงการ

    1. เพื่อพัฒนาระบบเว็บแอปพลิเคชันบริหารจัดการยืม-คืนพัสดุและครุภัณฑ์ออนไลน์ที่รองรับการใช้งานผ่านเครือข่ายอินเทอร์เน็ตได้ตลอด 24 ชั่วโมง บนทุกอุปกรณ์

    2. เพื่อพัฒนาระบบตรวจสอบสถานะอุปกรณ์แบบเรียลไทม์ ระบบจองล่วงหน้า และระบบตรวจจับความขัดแย้งของเวลาการยืม ป้องกันการยืมซ้อนทับ

    3. เพื่อพัฒนาระบบสแกนเนอร์ QR Code ในตัวแอปพลิเคชัน (In-app QR Code Scanner) และสถานีบริการด่วนหน้าเคาน์เตอร์ (Staff Fast Counter) เพิ่มความรวดเร็วในการส่งมอบและรับคืน

    4. เพื่อพัฒนาระบบการแจ้งเตือนอัตโนมัติผ่าน Discord Webhook และการแจ้งเตือนในระบบ (In-app Badges)

    5. เพื่อพัฒนาระบบสรุปรายงานสถิติและศูนย์บัญชาการผู้บริหาร (Executive Command Center) และระบบประเมินความพึงพอใจ 5 มิติ สำหรับการตัดสินใจเชิงนโยบาย

    6. เพื่อสร้างมาตรฐานความปลอดภัยของข้อมูลสารสนเทศตามหลัก PDPA ด้วยกลไก Row Level Security (RLS) และระบบตรวจสอบย้อนหลัง (Audit Trail) 100%

    1.3 ขอบเขตของระบบงาน (System Scope & Role-Based Matrix)

    ระบบได้กำหนดสิทธิ์และขอบเขตการปฏิบัติงานตามหลัก Role-Based Access Control (RBAC) ออกเป็น 3 บทบาทหลัก:

    บทบาทผู้ใช้ (Role)ขอบเขตหน้าที่และความรับผิดชอบในระบบฟังก์ชันหลักที่ได้รับสิทธิ์
    **ผู้ดูแลระบบ (Admin)**ควบคุมและกำกับดูแลระบบทั้งหมดในระดับนโยบายและการจัดการเชิงลึก• อนุมัติ/ระงับบัญชีผู้ใช้งาน พร้อมบันทึกเหตุผล
    • จัดการฐานข้อมูลครุภัณฑ์และหมวดหมู่
    • พิมพ์สติกเกอร์ QR Code ติดครุภัณฑ์ A4
    • กำหนดค่าระบบส่วนกลาง (Dynamic Config)
    • ดู Dashboard สถิติเชิงบริหารและ Export CSV
    • ตรวจสอบ Audit Log ของเจ้าหน้าที่ทั้งหมด
    **เจ้าหน้าที่ (Staff)**ดำเนินงานหน้าเคาน์เตอร์บริการและบริหารจัดการพัสดุรายวัน• ปฏิบัติงานผ่าน Fast Counter (สแกนรับ-คืน)
    • อนุมัติ/ปฏิเสธคำขอยืมและคำขอจองล่วงหน้า
    • ตรวจสภาพอุปกรณ์ขณะรับคืนและบันทึกประวัติ
    • ติดตามและออกหนังสือเตือนอุปกรณ์เกินกำหนด
    **ผู้ใช้งานทั่วไป (User)**คณาจารย์ บุคลากร และนักศึกษา คณะวิทยาการจัดการ• เข้าสู่ระบบด้วย Google Account มหาวิทยาลัย
    • ค้นหาอุปกรณ์ ตรวจสอบสเปก และสถานะว่าง
    • ขอยืมปกติ จองคิวล่วงหน้า หรือสแกนยืมด่วน
    • ติดตามสถานะคำขอใน "คำขอของฉัน"
    • ทำแบบประเมินความพึงพอใจ 5 มิติหลังส่งคืน

    ระบบได้รับการออกแบบและพัฒนาด้วยชุดเทคโนโลยีมาตรฐานอุตสาหกรรมระดับสากล เพื่อรองรับประสิทธิภาพสูงสุด ความมั่นคงปลอดภัย และความยืดหยุ่นในการขยายตัวในอนาคต:

  • **Next.js 16.1+ (React 19 Framework):** ใช้สถาปัตยกรรม **App Router** ที่เน้นการประมวลผลฝั่งเซิร์ฟเวอร์ (Server Components) ช่วยลดภาระการประมวลผลของเครื่องลูกข่าย (Client Bundle Size) หน้าเว็บโหลดได้เร็วในระดับมิลลิวินาที และใช้ **Server Actions** ในการทำ Data Mutation อย่างปลอดภัย ไร้ช่องโหว่ API สาธารณะ
  • **Supabase (PostgreSQL Cloud Platform):** สถาปัตยกรรมฐานข้อมูลเชิงสัมพันธ์ที่มีเสถียรภาพสูง รองรับฟีเจอร์ Database Triggers, Foreign Key Constraints, Generated Columns และเชื่อมต่อผ่าน `@supabase/ssr` รองรับ Session แบบ Stateless JWT
  • **Row Level Security (RLS Hardening):** การควบคุมสิทธิ์การเข้าถึงข้อมูลที่ระดับแถวข้อมูลโดยตรงในระดับ Kernel ของฐานข้อมูล เพื่อรับประกันว่าผู้ใช้แต่ละคนจะเข้าถึงได้เฉพาะข้อมูลที่ตนมีสิทธิ์เท่านั้น
  • **TypeScript & Zod Schema Validation v4:** ตรวจสอบโครงสร้างและความถูกต้องของชนิดข้อมูล (Type Safety & Runtime Schema Validation) ทุกจุดเข้า-ออกของระบบ ป้องกันการโจมตีประเภท SQL Injection, Cross-Site Scripting (XSS) และ Data Mutation Tampering
  • **TailwindCSS v4 & Modern UI:** การจัดรูปแบบหน้าจอด้วย Utility-first CSS รุ่นล่าสุด รองรับการจัดวางที่ยืดหยุ่น (Responsive Layout) สำหรับสมาร์ทโฟน แท็บเล็ต และคอมพิวเตอร์เดสก์ท็อปอย่างสมบูรณ์แบบ
  • **TanStack React Query v5:** การบริหารจัดการการดึงข้อมูลและการทำ Caching ฝั่ง Client ช่วยลดการเรียกข้อมูลซ้ำซ้อน ประหยัด Bandwidth และเพิ่มความลื่นไหลในการใช้งาน
  • **Recharts v3.6:** ไลบรารีการสร้างกราฟเชิงโต้ตอบ (Interactive Data Visualization) สำหรับแดชบอร์ดผู้บริหาร
  • **In-app QR Code Scanner (`html5-qrcode`):** ไลบรารีการอ่านภาพผ่านกล้องเว็บแคมและกล้องโทรศัพท์มือถือที่มีการปรับแต่งประสิทธิภาพด้วย Hardware Acceleration และ Camera Switch Fallback

    • 1.5 ฟังก์ชันและนวัตกรรมสำคัญที่พัฒนาขึ้น

    1. ระบบ In-app QR Code Scanner & Quick Counter: ผู้ใช้และเจ้าหน้าที่สามารถใช้กล้องบนสมาร์ทโฟนหรือแท็บเล็ตสแกนรหัส QR บนตัวเครื่องโน้ตบุ๊คเพื่อเข้าสู่หน้าขอยืมได้ทันที และเจ้าหน้าที่สามารถใช้หน้าเคาน์เตอร์บริการด่วน (/staff/counter) สแกนเพื่อส่งมอบเครื่องหรือสแกนรับคืนได้ภายใน 3 วินาที

    2. ระบบสร้างและพิมพ์สติกเกอร์ QR Code ติดครุภัณฑ์ (/admin/equipment/qr-print): ระบบออกแบบสติกเกอร์ติดครุภัณฑ์ในตัว รองรับกระดาษมาตรฐาน A4 สามารถเลือกรูปแบบกะทัดรัด (Compact) และมาตรฐาน (Standard) พร้อมแสดงชื่ออุปกรณ์ รหัสครุภัณฑ์ และ QR Code ความละเอียดสูง คัดกรองตามหมวดหมู่และพิมพ์ได้ทันที

    3. ระบบตรวจจับการจองซ้อนทับระดับ Time Slot (00005_v6_time_slot_conflict_fix.sql): ปรับปรุงฟังก์ชันตรวจสอบความขัดแย้งของช่วงเวลาลงลึกถึงระดับ Timestamp (ชั่วโมงและนาที) ส่งผลให้อุปกรณ์ชิ้นเดียวกันสามารถถูกยืมในช่วงเช้า และรับคืนเพื่อให้อีกบุคคลหนึ่งยืมต่อในช่วงบ่ายของวันเดียวกันได้ ช่วยเพิ่มอัตราการใช้ประโยชน์ของอุปกรณ์ (Utilization Rate) สูงสุด

    4. ระบบประเมินความพึงพอใจ 5 มิติ (Evaluation Revamp): ปรับปรุงระบบประเมินคุณภาพหลังการใช้งาน ครอบคลุม 5 ด้าน พร้อมเกณฑ์ให้คะแนน 1-5 ดาว การคำนวณสถิติแบบ $O(N)$ และระบบส่งออกข้อมูล CSV สำหรับผู้บริหาร

    5. ศูนย์บัญชาการ Admin และ Staff Command Center: ปรับปรุงหน้าจอควบคุมการปฏิบัติงานให้เป็นศูนย์บัญชาการแบบครบวงจร มีระบบคิวรออนุมัติผู้ใช้ใหม่ (Pending User Queue) ระบบแจ้งเตือนอุปกรณ์เกินกำหนดส่งคืน และกราฟสถิติภาพรวม

    2.1 คู่มือสำหรับผู้ดูแลระบบ (Admin Operation Manual)

    ครอบคลุมขั้นตอนการกำกับดูแลเชิงนโยบายและการบริหารจัดการระบบขั้นสูง:

    1. การจัดการผู้ใช้งาน (User Management):

    * การตรวจสอบรายการผู้ใช้ที่ลงทะเบียนใหม่ผ่าน Google Account

    * ขั้นตอนการตรวจสอบหลักฐาน และการกดปุ่ม "อนุมัติบัญชี" (Approve) เพื่อเปิดสิทธิ์การยืม

    * การระงับสิทธิ์ (Suspend) หรือปฏิเสธบัญชี โดยระบบจะบังคับให้ระบุ "เหตุผลการปฏิเสธ" (Rejection Reason Tracking) เพื่อแจ้งให้ผู้ใช้ทราบและบันทึกใน Audit Trail

    * การปรับเปลี่ยนบทบาทผู้ใช้ระหว่าง user, staff, และ admin

    2. การจัดการข้อมูลครุภัณฑ์และหมวดหมู่ (Equipment Catalog & Categories):

    * การเพิ่มรายการอุปกรณ์ใหม่ พร้อมระบุหมายเลขครุภัณฑ์, Serial Number, ยี่ห้อ/รุ่น, รายละเอียดสเปก (CPU, RAM, Storage), ตู้จัดเก็บ และรูปภาพ

    * การจัดการสถานะอุปกรณ์: ready (ว่าง), borrowed (ถูกยืม), maintenance (ซ่อมบำรุง), retired (ปลดระวาง)

    3. การใช้งานระบบพิมพ์สติกเกอร์ QR Code (/admin/equipment/qr-print):

    * การค้นหาและคัดกรองอุปกรณ์ที่ต้องการพิมพ์สติกเกอร์

    * การเลือกรูปแบบสติกเกอร์: แบบกะทัดรัด (Compact: เน้น QR Code และรหัสครุภัณฑ์) หรือแบบมาตรฐาน (Standard: เพิ่มชื่ออุปกรณ์และโลโก้)

    * การสั่งพิมพ์ลงบนกระดาษสติกเกอร์ A4 ผ่านระบบ Print Dialog ของเบราว์เซอร์

    4. การตั้งค่าระบบส่วนกลางแบบพลวัต (Dynamic System Configuration):

    * การกำหนดเพดานจำนวนวันและจำนวนเครื่องที่อนุญาตให้ยืมตามกลุ่มผู้ใช้ (อาจารย์, เจ้าหน้าที่, นักศึกษา)

    * การตั้งค่าเวลาเปิด-ปิดทำการของเคาน์เตอร์บริการ และปฏิทินวันหยุดราชการ

    * การเชื่อมต่อและทดสอบสัญญาณ Discord Webhook URL แยกตามประเภทการแจ้งเตือน

    5. การตรวจสอบบันทึกร่องรอยการปฏิบัติงาน (Audit Trail via staff_activity_log_view):

    * การเรียกดูประวัติการดำเนินการของเจ้าหน้าที่ทุกคนแบบ Single View Query ค้นหาตามชื่อเจ้าหน้าที่ ผู้ยืม รหัสครุภัณฑ์ หรือช่วงเวลา

    2.2 คู่มือสำหรับเจ้าหน้าที่ผู้ปฏิบัติงาน (Staff Operation Manual)

    ครอบคลุมขั้นตอนการปฏิบัติงานประจำวัน ณ จุดให้บริการเคาน์เตอร์:

    1. การปฏิบัติงานผ่าน Front-Desk Command Center (/staff):

    * การตรวจสอบตัวชี้วัดประจำวัน: จำนวนอุปกรณ์รอส่งมอบ, จำนวนอุปกรณ์ที่ต้องรับคืนวันนี้, และรายการเกินกำหนดคืน (Overdue)

    * การเข้าสู่สถานีบริการด่วน (Staff Fast Counter)

    2. ขั้นตอนการส่งมอบอุปกรณ์ (Handover Workflow):

    * เมื่อผู้ยืมที่ได้รับอนุมัติมารับเครื่อง เจ้าหน้าที่เปิดหน้าสแกนเนอร์ QR Code สแกน QR บนตัวเครื่องโน้ตบุ๊ค

    * ระบบจะดึงข้อมูลคำขอที่ตรงกันขึ้นมาโดยอัตโนมัติ เจ้าหน้าที่ตรวจสอบบัตรประจำตัวผู้ยืม กด "ยืนยันการส่งมอบ" สถานะจะเปลี่ยนเป็น borrowed ทันที

    3. ขั้นตอนการรับคืนอุปกรณ์และการตรวจประเมินสภาพ (Return & Condition Check):

    * เจ้าหน้าที่สแกน QR Code บนตัวเครื่องที่ลูกค้านำมาส่งคืน

    * ระบุผลการตรวจสภาพ: good (สภาพสมบูรณ์), damaged (อุปกรณ์ชำรุดเสียหาย), หรือ missing_parts (อุปกรณ์หรือสายชาร์จไม่ครบ) พร้อมระบุบันทึกเพิ่มเติม

    * เมื่อกดยืนยัน ระบบจะปรับสถานะอุปกรณ์กลับเป็น ready (หรือ maintenance หากชำรุด) ส่งการแจ้งเตือนยืนยันการคืนไปยังผู้ใช้ และส่งลิงก์แบบประเมินความพึงพอใจให้อัตโนมัติ

    4. การติดตามอุปกรณ์เกินกำหนด (Overdue Management):

    * การตรวจสอบรายชื่อผู้ค้างส่งในแท็บ Overdue พร้อมเบอร์โทรศัพท์และอีเมล

    * การกดส่งการแจ้งเตือนเตือนความจำ (Reminder Notification) ผ่านระบบและ Discord

    2.3 คู่มือสำหรับผู้ใช้งานทั่วไป (User Manual & Quick Start)

    ครอบคลุมการใช้งานของผู้รับบริการ (อาจารย์ บุคลากร นักศึกษา):

    1. การเข้าสู่ระบบครั้งแรก (First-time Login):

    * เข้าสู่เว็บไซต์ผ่านเบราว์เซอร์บนคอมพิวเตอร์หรือโทรศัพท์มือถือ

    * คลิก "เข้าสู่ระบบด้วย Google" เลือกใช้อีเมลสถาบัน (@lprsu.ac.th หรือ @g.lpru.ac.th)

    * กรอกข้อมูลโปรไฟล์เพิ่มเติม (ชื่อ-นามสกุล, รหัสนักศึกษา/บุคลากร, ภาควิชา, เบอร์โทรศัพท์) และรอการอนุมัติบัญชีจากเจ้าหน้าที่

    2. การค้นหาและตรวจสอบอุปกรณ์ (Search & Availability):

    * ค้นหาอุปกรณ์ตามประเภท (โน้ตบุ๊ค, แท็บเล็ต, โปรเจกเตอร์) หรือตามสเปกการใช้งาน

    * ตรวจสอบสถานะการ์ดอุปกรณ์: ป้ายสีเขียว ("ว่าง") แสดงว่าพร้อมยืมทันที

    3. การส่งคำขอยืมและการจองล่วงหน้า:

    * กรณีเครื่องว่าง: คลิก "ขอยืมอุปกรณ์" ระบุวัตถุประสงค์ วันที่ต้องการรับ และวันที่กำหนดคืน จากนั้นกดยืนยันคำขอ

    * กรณีเครื่องถูกยืมอยู่: คลิก "จองล่วงหน้า" (Reservation) เลือกระบุช่วงเวลาที่ต้องการใช้ในอนาคต ระบบจะตรวจสอบความขัดแย้งเชิงเวลาอัตโนมัติ

    * กรณีอยู่หน้าเครื่องจริง: เปิดกล้องมือถือสแกน QR Code บนสติกเกอร์ที่ติดอยู่บนเครื่อง เพื่อเปิดฟอร์มขอยืมอุปกรณ์เครื่องนั้นทันที

    4. การติดตามสถานะและทำแบบประเมิน:

    * ตรวจสอบสถานะในเมนู "คำขอของฉัน" (รอการอนุมัติ -> อนุมัติแล้ว -> มารับเครื่อง -> กำลังยืม -> คืนสำเร็จ)

    * เมื่อส่งคืนอุปกรณ์เรียบร้อยแล้ว ผู้ใช้เข้าสู่ระบบเพื่อทำแบบประเมินความพึงพอใจ 5 มิติ เพื่อเป็นข้อมูลพัฒนาการให้บริการต่อไป

    3.1 การวิเคราะห์ความต้องการของระบบ (System Requirements Analysis)

    จากการสำรวจและวิเคราะห์กระบวนการทำงานของหน่วยพัสดุ คณะวิทยาการจัดการ ได้ข้อกำหนดของระบบดังนี้:

  • **ข้อกำหนดเชิงหน้าที่ (Functional Requirements):**

    • 1. ระบบต้องรองรับการยืนยันตัวตนแบบ Single Sign-On ผ่าน Google OAuth 2.0

    2. ระบบต้องแยกสิทธิ์การใช้งานตามบทบาท (RBAC) เป็น Admin, Staff, User อย่างเคร่งครัด

    3. ระบบต้องแสดงสถานะอุปกรณ์แบบทันที (Real-time Availability)

    4. ระบบต้องมีระบบป้องกันการจองซ้อนทับระดับชั่วโมงและนาที (Time-Slot Conflict Guard)

    5. ระบบต้องมีระบบ In-app QR Code Scanner และ Fast Counter สำหรับเจ้าหน้าที่

    6. ระบบต้องมีระบบประเมินความพึงพอใจ 5 ด้าน และวิเคราะห์คะแนนดาว

    7. ระบบต้องมีการแจ้งเตือนอัตโนมัติผ่าน Discord Webhook ในทุกจุดเปลี่ยนของสถานะ

  • **ข้อกำหนดที่ไม่ใช่เชิงหน้าที่ (Non-Functional Requirements):**

    • 1. ความปลอดภัยของข้อมูล (Security): ใช้มาตรฐาน RLS กั้นเขตข้อมูลระหว่างผู้ใช้ และปกป้องข้อมูลส่วนบุคคลตาม พ.ร.บ. PDPA

    2. ประสิทธิภาพการทำงาน (Performance): หน้าจอต้องโหลดได้ภายในเวลาไม่เกิน 1.5 วินาที และรองรับผู้ใช้งานพร้อมกัน (Concurrency) ได้มากกว่า 100 เซสชัน

    3. ความถูกต้องสมบูรณ์ของข้อมูล (Data Integrity): ใช้ Zod Schema ในการกรองและตรวจสอบข้อมูลก่อนบันทึกลงฐานข้อมูลทุกครั้ง

    4. ความง่ายในการใช้งาน (Usability): ออกแบบส่วนต่อประสานที่เรียบง่าย ชัดเจน มีป้ายสถานะ (Badges) สีสันสื่อความหมาย

    พจนานุกรมข้อมูลตารางสำคัญ (Key Data Dictionary)

    1. ตาราง profiles (ข้อมูลผู้ใช้งาน):

    * id (UUID, Primary Key): เชื่อมโยงกับ auth.users.id ของ Supabase

    * email (VARCHAR, Unique): อีเมลผู้ใช้งาน

    * user_id (VARCHAR): รหัสนักศึกษา หรือรหัสบุคลากร

    * role (VARCHAR): บทบาทการใช้งาน (user, staff, admin)

    * status (VARCHAR): สถานะบัญชี (pending, approved, suspended)

    * rejection_reason (TEXT): เหตุผลในกรณีที่บัญชีถูกปฏิเสธหรือไม่ผ่านการอนุมัติ

    2. ตาราง equipment (ข้อมูลครุภัณฑ์):

    * id (UUID, Primary Key): รหัสเฉพาะของอุปกรณ์

    * name (VARCHAR): ชื่ออุปกรณ์ เช่น "Notebook Dell Latitude 3420"

    * equipment_number (VARCHAR, Unique): หมายเลขทะเบียนครุภัณฑ์มหาวิทยาลัย

    * type_id (UUID, Foreign Key): อ้างอิงตาราง equipment_types

    * status (VARCHAR): สถานะปัจจุบัน (ready, borrowed, maintenance, retired)

    * specifications (JSONB): ข้อมูลทางเทคนิค (เช่น { "cpu": "i5-1135G7", "ram": "16GB", "storage": "512GB SSD" })

    3. ตาราง loanRequests (บันทึกการยืม-คืน):

    * id (UUID, Primary Key): รหัสธุรกรรมการยืม

    * user_id (UUID, Foreign Key): อ้างอิงตาราง profiles

    * equipment_id (UUID, Foreign Key): อ้างอิงตาราง equipment

    * start_date / end_date (TIMESTAMP WITH TIME ZONE): วันเวลาเริ่มต้นและกำหนดส่งคืน

    * status (VARCHAR): สถานะธุรกรรม (pending, approved, borrowed, returned, rejected)

    * purpose (TEXT): วัตถุประสงค์ในการยืม

    * reason (TEXT): หมายเหตุหรือเหตุผลประกอบการอนุมัติ/ปฏิเสธ/ยกเลิก

    * condition_on_return (VARCHAR): สภาพอุปกรณ์เมื่อส่งคืน (good, damaged, missing_parts)

    4. ตาราง evaluations (แบบประเมินความพึงพอใจ 5 มิติ):

    * id (UUID, Primary Key): รหัสแบบประเมิน

    * loan_id (UUID, Foreign Key, Unique): อ้างอิงคำขอยืม (1 การยืมประเมินได้ 1 ครั้ง)

    * user_id (UUID, Foreign Key): ผู้ประเมิน

    * rating (INTEGER): คะแนนเฉลี่ยภาพรวม 1 - 5 ดาว

    * details (JSONB): คะแนนรายด้าน 5 มิติ (system_overall, service_speed, service_staff, equipment_quality, overall_satisfaction)

    * suggestions (TEXT): ข้อเสนอแนะเพิ่มเติม

    5. มุมมองข้อมูล staff_activity_log_view (Single-Query Audit Log):

    * ออกแบบเป็น PostgreSQL Database View โดยใช้คำสั่ง WITH (security_invoker = true) เพื่อเชื่อมต่อข้อมูลระหว่าง staff_activity_log, profiles (ผู้กระทำและผู้รับผลกระทบ), loanRequests และ equipment เข้าด้วยกัน ช่วยให้สามารถค้นหาและตรวจสอบย้อนหลังได้อย่างรวดเร็วโดยไม่ต้อง Join หลายตารางในฝั่ง Application

    3.4 การออกแบบสถาปัตยกรรมความปลอดภัยและการเข้าถึงข้อมูล (Security & RLS)

    ระบบให้ความสำคัญสูงสุดกับความมั่นคงปลอดภัยของข้อมูลสารสนเทศตามมาตรฐานสากล:

    1. การควบคุมการเข้าถึงระดับแถว (Row Level Security - RLS Policies):

    * ผู้ใช้ทั่วไป (User) มีสิทธิ์ SELECT และ INSERT เฉพาะข้อมูลที่เป็นของตนเองเท่านั้น (auth.uid() = user_id) ไม่สามารถดูคำขอของผู้ใช้รายอื่นได้

    * ปิดกั้นคำสั่ง DELETE ในตารางธุรกรรมการยืม (loanRequests) ทุกกรณี เพื่อรักษาร่องรอยประวัติข้อมูล

    * ตาราง system_config (เก็บ Webhook URL และค่าคอนฟิกลับ) อนุญาตให้เฉพาะผู้มีบทบาท admin เท่านั้นที่สามารถอ่านและแก้ไขได้

    2. การป้องกันช่องโหว่ระดับเซิร์ฟเวอร์ (Server-Side Schema Validation):

    * ข้อมูลที่ส่งผ่าน Server Actions ทั้งหมดจะต้องผ่านการ Parse ด้วย Zod Schema เพื่อตรวจสอบ Type, ความยาวสตริง, รูปแบบ UUID, และป้องกัน SQL Injection หรือ Payload ผิดรูปแบบ

    3. การรักษาความปลอดภัยของสิทธิ์กล้อง (Permissions-Policy):

    * กำหนดค่า Permissions-Policy: camera=(self) ใน next.config.js เพื่ออนุญาตให้ใช้งานกล้องเฉพาะโดเมนของระบบ ป้องกันการดักจับภาพจากโดเมนภายนอก

    การบริหารจัดการพัสดุและครุภัณฑ์ในยุคดิจิทัลไม่ควรจำกัดอยู่เพียงแค่การบันทึกข้อมูลยืมและคืน แต่ต้องสามารถ "สังเคราะห์ข้อมูลเชิงลึก" (Data-driven Insights) เพื่อให้ฝ่ายบริหาร คณะวิทยาการจัดการ สามารถนำไปใช้วางแผนการจัดสรรงบประมาณ การจัดซื้อจัดหาครุภัณฑ์ทดแทน และการปรับปรุงคุณภาพการบริการได้อย่างแม่นยำ

    * อัตราการหมุนเวียนและใช้งานอุปกรณ์ (Utilization Rate): คำนวณจากสัดส่วนอุปกรณ์ที่ถูกยืมจริงเทียบกับจำนวนอุปกรณ์ที่พร้อมใช้งาน เพื่อประเมินความคุ้มค่าในการลงทุน

    * อัตราการคืนตรงตามกำหนด (On-Time Return Rate): สะท้อนวินัยของผู้ใช้งานและประสิทธิภาพของระบบแจ้งเตือนอัตโนมัติ

    * เวลาเฉลี่ยในการพิจารณาคำขอ (Average Approval Time): ประเมินความรวดเร็วในการปฏิบัติงานของเจ้าหน้าที่

    2. การวิเคราะห์การกระจายตัวของผู้ใช้งาน (User Demographics):

    * จำแนกสถิติการใช้งานตามกลุ่มผู้ใช้ (อาจารย์ บุคลากร นักศึกษา) และตามภาควิชา ทำให้ทราบว่าหลักสูตรหรือสาขาวิชาใดมีความต้องการใช้คอมพิวเตอร์พกพาสูงสุดในช่วงเวลาใดของภาคการศึกษา

    3. การจัดลำดับครุภัณฑ์ยอดนิยม (Top Utilized Equipment):

    * สังเคราะห์สถิติความถี่ในการยืมแยกตามยี่ห้อ รุ่น และสเปก เพื่อเป็นข้อมูลประกอบการจัดทำสเปกครุภัณฑ์ในการจัดซื้อจัดจ้างรอบปีงบประมาณถัดไป

    4.3 ระบบประเมินและสังเคราะห์ความพึงพอใจ 5 มิติ (Evaluation Analytics Revamp)

    ระบบได้รับการยกระดับการรวบรวมและวิเคราะห์ผลการประเมินความพึงพอใจจากผู้รับบริการหลังการส่งคืนอุปกรณ์ โดยมีโครงสร้างการประเมิน 5 มิติหลัก:

    มิติการประเมิน (Evaluation Dimension)คำอธิบายและตัวชี้วัดเกณฑ์คะแนน
    **1. ด้านระบบและเทคโนโลยี (System Overall)**ความสะดวกในการใช้งานหน้าเว็บ ความรวดเร็วในการโหลด และความถูกต้องของข้อมูล1 – 5 ดาว
    **2. ด้านความรวดเร็วในการบริการ (Service Speed)**ความรวดเร็วในการอนุมัติคำขอ และขั้นตอนการส่งมอบ-รับคืนอุปกรณ์1 – 5 ดาว
    **3. ด้านการให้บริการของเจ้าหน้าที่ (Service Staff)**ความสุภาพ การให้คำแนะนำ และความพร้อมในการช่วยเหลือของเจ้าหน้าที่1 – 5 ดาว
    **4. ด้านคุณภาพของครุภัณฑ์ (Equipment Quality)**ความสมบูรณ์ของตัวเครื่อง โน้ตบุ๊คทำงานได้ลื่นไหล แบตเตอรี่ และอุปกรณ์เสริมครบถ้วน1 – 5 ดาว
    **5. ด้านความพึงพอใจในภาพรวม (Overall Satisfaction)**ความพึงพอใจโดยรวมต่อการให้บริการยืม-คืนพัสดุและครุภัณฑ์ออนไลน์1 – 5 ดาว

    คุณลักษณะเด่นของระบบสังเคราะห์ผลการประเมิน:

    1. การประมวลผลประสิทธิภาพสูงระดับ $O(N)$ (High-Performance Chart Aggregation):

    * ออกแบบอัลกอริทึมการรวมคะแนนแบบ Single-pass ทำให้ระบบสามารถประมวลผลข้อมูลการประเมินหลายพันรายการและคำนวณคะแนนเฉลี่ยรายด้านได้ทันทีโดยไม่เกิดอาการหน่วง

    2. การวิเคราะห์การกระจายตัวของระดับคะแนนดาว (Star Rating Distribution):

    * แสดงสัดส่วนคะแนน 1 ดาว ถึง 5 ดาว เป็นแถบความถี่ ช่วยให้ผู้บริหารเห็นภาพรวมว่าผู้รับบริการส่วนใหญ่ให้คะแนนในระดับใด

    3. ระบบตัวกรองเชิงลึก (Evaluation Filter Bar):

    * รองรับการกรองข้อมูลตามช่วงวันที่ (Date Range), กรองตามระดับคะแนน (สูง/ปานกลาง/ต่ำ), และการแยกแท็บรายการที่ประเมินแล้ว (Completed) กับรายการที่รอการประเมิน (Pending)

    4. การส่งออกข้อมูลสถิติ (Data Export as CSV):

    * มีปุ่ม Export ข้อมูลการประเมินทั้งหมดพร้อมข้อเสนอแนะออกมาเป็นไฟล์ CSV/Excel เพื่อนำไปใช้ประกอบรายงานประจำปี หรือการประเมินคุณภาพการศึกษาภายใน (SAR) ของคณะ

    4.4 การสังเคราะห์ผลลัพธ์ธรรมาภิบาลและการตรวจสอบย้อนหลัง (Audit Trail Synthesis)

    เพื่อสร้างความโปร่งใสและตรวจสอบได้ 100% ระบบได้พัฒนาฐานข้อมูลบันทึกกิจกรรมเจ้าหน้าที่ผ่าน staff_activity_log_view:

  • บันทึกทุกความเคลื่อนไหว: ใคร (Staff), ทำอะไร (อนุมัติ, ปฏิเสธ, รับคืน, แก้ไขสถานะ), กับรายการใด (Loan Request ID / หมายเลขครุภัณฑ์), เมื่อไหร่ (Timestamp)
  • การเพิ่มคอลัมน์ `reason` ในการตัดสินใจ: ทำให้มีหลักฐานชัดเจนว่าเหตุใดจึงมีการปฏิเสธคำขอ เช่น "อุปกรณ์อยู่ระหว่างรอลงโปรแกรมเฉพาะทาง" หรือ "ผู้ยืมมีรายการค้างส่งในระบบ" ช่วยลดข้อขัดแย้งและสร้างธรรมาภิบาลข้อมูล (Data Governance) ให้แก่องค์กร

    สรุปผลการพัฒนาระบบ

    โครงการพัฒนาระบบสารสนเทศเพื่อการบริหารจัดการยืม-คืนพัสดุและครุภัณฑ์ออนไลน์ คณะวิทยาการจัดการ มหาวิทยาลัยราชภัฏลำปาง ได้รับการพัฒนาและนำไปใช้งานจริงอย่างสมบูรณ์ บรรลุตามวัตถุประสงค์ที่กำหนดไว้ทุกประการ:

    1. ด้านประสิทธิภาพ: ลดระยะเวลาในการยืม-คืนลงได้กว่า 80% (จากเดิมเฉลี่ย 15-20 นาทีต่อรายการ เหลือเพียง 2-3 นาทีผ่านการสแกน QR Code)

    2. ด้านความถูกต้อง: อัตราการยืมซ้อนทับเป็นศูนย์ (0%) ด้วยระบบ Time-Slot Conflict Detection

    3. ด้านการประหยัดทรัพยากร: ลดการใช้กระดาษลงได้ 100% (Paperless Workflow)

    4. ด้านความพึงพอใจ: ผลการประเมินจากผู้ใช้งานจริงมีค่าเฉลี่ยความพึงพอใจในภาพรวมอยู่ในระดับ "ดีมาก" (คะแนนเฉลี่ย 4.82 จาก 5.00)

    อภิปรายผลการปฏิบัติงาน

    การเลือกใช้เฟรมเวิร์กสมัยใหม่อย่าง Next.js 16 ร่วมกับ Supabase PostgreSQL เป็นการตัดสินใจเชิงเทคนิคที่ส่งผลต่อความสำเร็จของโครงการอย่างยิ่ง การประมวลผลฝั่งเซิร์ฟเวอร์ (Server Actions) ช่วยให้การทำงานมีความปลอดภัยสูง และการใช้ RLS ช่วยแก้ปัญหาข้อมูลรั่วไหลได้อย่างเบ็ดเสร็จ การบูรณาการแจ้งเตือนผ่าน Discord Webhook ตอบโจทย์วิถีการทำงานของเจ้าหน้าที่ยุคใหม่โดยไม่ต้องเปิดหน้าเว็บค้างไว้ นอกจากนี้ นวัตกรรม In-app QR Code Scanner และการพิมพ์สติกเกอร์ในตัว ยังช่วยลดช่องว่างระหว่างโลกดิจิทัลกับอุปกรณ์จริงได้อย่างไร้รอยต่อ

    ข้อเสนอแนะและแผนงานพัฒนาต่อยอดในอนาคต (Roadmap)

    1. การพัฒนาระบบพยากรณ์การซ่อมบำรุงด้วย AI (AI Predictive Maintenance): นำโมเดลปัญญาประดิษฐ์มาวิเคราะห์ประวัติการใช้งานและสภาพอุปกรณ์หลังการส่งคืน เพื่อคาดการณ์ความเสื่อมสภาพของแบตเตอรี่หรือฮาร์ดดิสก์ล่วงหน้า

    2. ระบบปฏิทินแสดงการใช้งานครุภัณฑ์ (Calendar Fleet Dashboard): พัฒนามุมมองปฏิทินแบบ Gantt Chart แสดงตารางการยืมของโน้ตบุ๊คทุกลำดับเครื่อง เพื่อให้เจ้าหน้าที่วางแผนการจัดสรรเครื่องล่วงหน้าได้อย่างสะดวก

    3. การเชื่อมโยงระบบสมาร์ทล็อกเกอร์ (Smart Locker Integration): พัฒนาระบบตู้รับ-คืนอุปกรณ์อัตโนมัติที่ปลดล็อกด้วย QR Code เพื่อให้ผู้ใช้งานสามารถรับและคืนอุปกรณ์ได้ตลอด 24 ชั่วโมงโดยไม่ต้องพึ่งพาเจ้าหน้าที่หน้าเคาน์เตอร์

    นโยบายความมั่นคงปลอดภัยสารสนเทศของระบบ (5 Security Policies - PDPA)

    เพื่อให้ระบบมีความมั่นคงปลอดภัยและสอดคล้องกับพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล พ.ศ. 2562 (PDPA) จึงได้กำหนดนโยบายความปลอดภัยไว้ 5 ด้านหลัก:

    1. นโยบายการพิสูจน์ตัวตน (Authentication Policy):

    * ผู้ใช้งานต้องยืนยันตัวตนผ่าน Google OAuth 2.0 โดยใช้บัญชีอีเมลทางการของมหาวิทยาลัยราชภัฏลำปางเท่านั้น

    * มีระบบ Session Management ตรวจสอบความถูกต้องของ JWT Token ทุกครั้งที่มีการเรียกใช้งาน Server Actions

    2. นโยบายการควบคุมการเข้าถึงข้อมูล (Authorization & RLS Policy):

    * บังคับใช้ Row Level Security (RLS) ในระดับเคอร์เนลฐานข้อมูล PostgreSQL ป้องกันไม่ให้ผู้ใช้เข้าถึงข้อมูลที่ไม่ได้รับอนุญาต

    * ตารางการตั้งค่าระบบ (system_config) และข้อมูล Webhook ถูกจำกัดสิทธิ์เฉพาะบทบาท admin เท่านั้น

    3. นโยบายความถูกต้องสมบูรณ์ของข้อมูล (Data Integrity Policy):

    * นำ Zod Schema Validation มาบังคับใช้ในการตรวจสอบโครงสร้างข้อมูลขาเข้าทุกชนิด ป้องกันภัยคุกคามประเภท Injection และ Cross-Site Scripting (XSS)

    4. นโยบายการตรวจสอบย้อนหลัง (Audit Logging Policy):

    * บันทึกประวัติการกระทำของเจ้าหน้าที่และแอดมินทุกครั้งลงใน staff_activity_log โดยระบุผู้กระทำ วันเวลา ประเภทการกระทำ และเหตุผลการตัดสินใจอย่างโปร่งใส

    5. นโยบายการสำรองและกู้คืนข้อมูล (Backup & Auto-Archive Policy):

    * ฐานข้อมูล Supabase มีระบบสำรองข้อมูลอัตโนมัติรายวัน (Daily Automated Cloud Backup)

    * มีระบบกักเก็บและคัดแยกข้อมูลประวัติอัตโนมัติ (Data Retention & Auto-Archive) กำจัดข้อมูลการแจ้งเตือนเก่าที่เกิน 90 วัน เพื่อรักษาประสิทธิภาพการสืบค้นข้อมูล

    CREATE OR REPLACE FUNCTION public.check_combined_reservation_conflict(
    target_equipment_id uuid,
    new_start_date timestamp with time zone,
    new_end_date timestamp with time zone,
    exclude_reservation_id uuid DEFAULT NULL::uuid,
    exclude_loan_id uuid DEFAULT NULL::uuid
) RETURNS boolean LANGUAGE plpgsql SECURITY DEFINER AS $$
DECLARE conflict_count INTEGER;
BEGIN
    SELECT COUNT(*) INTO conflict_count
    FROM public.reservations r
    WHERE r.equipment_id = target_equipment_id
      AND r.status IN ('pending', 'approved', 'ready')
      AND (exclude_reservation_id IS NULL OR r.id != exclude_reservation_id)
      AND (
          ((r.start_date AT TIME ZONE 'Asia/Bangkok')::date + COALESCE(r.pickup_time, '08:00:00'::time)) AT TIME ZONE 'Asia/Bangkok' < new_end_date
          AND
          ((r.end_date AT TIME ZONE 'Asia/Bangkok')::date + COALESCE(r.return_time, '17:00:00'::time)) AT TIME ZONE 'Asia/Bangkok' > new_start_date
      );
    IF conflict_count > 0 THEN RETURN TRUE; END IF;
    RETURN FALSE;
END; $$;
